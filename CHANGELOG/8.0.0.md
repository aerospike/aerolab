# [v8.0.0](https://github.com/aerospike-community/aerolab/releases/tag/8.0.0)

_Release Date: LongMonth Day, Year_

**Release Notes:**
* Complete rewrite of the backend code for `Docker`, `AWS` and `GCP`, using all API calls, no shell commands or external tool dependencies, and latest SDKs.
* Complete refactor of the CLI code, using new backend code and separating logic and functional code into it's own libraries.
* Full CLI parameter cleanup: consistent flag naming across all commands and namespaced backend-specific flags (`--aws.*`, `--gcp.*`, `--docker.*`); see the breaking-changes entry below.
* CLI: Add `inventory migrate` command to migrate inventory to the new AeroLab format and port SSH keys to the new AeroLab directory.
* CLI: Add `config migrate` command to migrate config to the new AeroLab directory.
* CLI: Add basic Aerospike Cloud support.
* Add `amazonlinux:2023` support in Docker backend.
* Add support for deploying `Ubuntu 26.04 LTS` (Resolute Raccoon) across the Docker, AWS and GCP backends. Aerospike Server packages for it start at 8.1.3, so earlier server versions will report which builds are available instead.
* Docker: Fix `rocky:10`, which could never start. AeroLab derived the base image from the `amd64/rockylinux` and `arm64v8/rockylinux` repositories, which were deprecated and never published anything past 9. Rocky Linux 10 is now taken from the multi-arch `rockylinux/rockylinux` repository, with the architecture pinned at build time as before. Rocky 8 and 9 are unchanged.
* `template create`: when no package matches the requested distro, version and architecture, the error now names the combination that failed and lists the OS builds the chosen Aerospike version actually ships, instead of only reporting that nothing matched.
* Add low-level CLI commands `aerolab instances` and `aerolab images` to manage instances and images.
* Remove obsolete Vector client integrations.
* Backend: ALL: The tags have changed names and format from AeroLab 7 to AeroLab 8.
* Performance: Parallelize everything possible to improve performance.
* Performance: Add option to cache inventory on local disk, massively improving performance and reducing API calls.
  * Added fallback command `aerolab inventory refresh-disk-cache` to force-refresh the whole disk cache (disk cache attempts to refresh changes automatically).
* Performance: Reduce number of API calls to the backends to the bare required minimum to improve performance of all commands.
* Performance, stability and security: Do NOT shell out to external tools for backend interaction, use the SDKs directly.
* Expiry system: Complete rewrite, using the new backend code, improving speed and stability.
* Logging: Improve logging, adding log levels and more detailed logging for troubleshooting.
* Docker: Use a systemd-compatible init system (`docker-systemd`) in order to unify experience across Docker, AWS and GCP backends.
  * This means that the docker containers now have ssh running inside them, and support `systemctl` commands to manage services.
* Aerolab binaries will be much smaller as they no longer embed linux-versions of themselves. Rather, if required, these are downloaded on demand.
* Added handling of certain environment variables documented in `docs/reference/environment-variables.md`.
* Moved default AeroLab directory from `~/.aerolab` to `~/.config/aerolab`.
* Added `aerolab instances update-hosts-file` command to update the `/etc/hosts` file on instances informing them of the other instances in the project.
  * Linked to `aerolab cluster update-hosts-file` and `aerolab client update-hosts-file` commands.
* Added support for AeroLab-level projects, set by the `AEROLAB_PROJECT` environment variable. Once set, all resources will be scoped to this project.
* Added `aerolab inventory delete-project-resources` command to delete all resources in the current aerolab project.
* CLI: WARN: Some paramters have been modified or removed, 100% backwards compatibility is not guaranteed.
* CLI: WARN: Inventory listing format has changed, including flags, output formats, table headers, and json output.
* AGI: AeroLab now supports creating AGI templates, to speed up instance creation and reduce failure points.
* AMS: AeroLab now supports creating AMS templates, to speed up instance creation and reduce failure points.
* AGI: AGI storage backend change, and tuning speeding up ingest and graph rendering (plugin).
* Implemented idempotent retry system on multiple cloud failure points throughout the code.
* AeroLab MCP built-in to the tool.
* `cluster partition conf`: clamp the computed `partition-tree-sprigs` to the Aerospike-documented range `[256, 268435456]` (power of 2), and refuse to write a config when even 256 sprigs do not fit the configured `mounts-budget`. Previously, small pi-flash partitions could cause aerolab to emit `partition-tree-sprigs 128`, which Aerospike rejects before logging (very painful to debug).
* CLI: BREAKING: Full command-line parameter cleanup for v8. Highlights:
  * Backend-specific flags are now namespaced everywhere (matching `instances create`): `--aws.<flag>`, `--gcp.<flag>`, `--docker.<flag>` in `cluster create/grow/apply`, `client create/grow` (all types), `xdr create-clusters`, `agi create`, `agi monitor create`, `template create`, `agi template create`, `client template ams create` and `config backend`. Examples: `--aws-disk`→`--aws.disk`, `--ami`→`--aws.image`, `-I/--instance-type`→`--aws.instance`, `--subnet-id`→`--aws.placement`, `--secgroup-name`→`--aws.firewall`, `--aws-spot-instance`→`--aws.spot`, `--external-ip`→`--gcp.public-ip`, `--gcp-vol-*`→`--gcp.vol-*`, `--on-host-maintenance-policy`→`--gcp.on-host-maintenance`, `--expose-ports`→`--docker.expose-ports`, `--cpu-limit`→`--docker.cpu-limit`, `--template-source`→`--docker.template-source`.
  * `client` commands now use `-n/--name` (was `--group-name`) and `-l/--nodes` (was `--machines`); clients and clusters are both instance groups underneath.
  * All parallelism flags unified to `--threads` (was a mix of `--threads`, `--parallel-threads` and `--parallel-ssh-threads`); short is `-t` where free, `-p` in create-style commands where `-t` is `--tag`.
  * `attach *` and `agi attach` node selectors renamed `--node`→`--nodes` (they accept lists); single-node parameters (e.g. `data insert -l`, `logs show -l`) remain `--node`.
  * `cluster create/apply`: `--customconf`→`--custom-conf`, `--toolsconf`→`--tools-conf`, `--featurefile`→`--feature-file`, `-m/--mode`→`-m/--heartbeat-mode`; per-backend tag/label flags (`--tags`, `--label`, `--docker-label`) unified into one top-level `-t/--tag key=value` applied to any backend.
  * `config backend`: `--aws-profile`→`--aws.profile`, `--aws-nopublic-ip`→`--aws.no-public-ip`, `-o/--project`→`--gcp.project`, `--gcp-nopublic-ip`→`--gcp.no-public-ip`, `--gcp-use-iap`→`--gcp.use-iap`, `--gcp-auto-enable-services`→`--gcp.auto-enable-services`, `--docker-arch`→`--docker.arch`, `--docker-registry-region`→`--docker.registry-region`.
  * `agi create`: `--agi-label`→`--label`, `--aws.instance-type`→`--aws.instance`, `--aws.subnet-id`→`--aws.placement`, `--aws.secgroup-id`→`--aws.firewall`, `--aws.tags`→`--aws.tag`, `--aws.efs-multizone`→`--aws.efs-multi-zone`, `--aws.route53-zoneid`→`--aws.route53-zone-id`, `--*.spot-instance`→`--*.spot`, `--*.disable-public-ip`→`--*.no-public-ip`, `--gcp.tag`→`--gcp.network-tag`, `--gcp.label`→`--gcp.tag`.
  * `agi monitor create`: `--aws.secgroup-id`→`--aws.firewall`, `--aws.secgroup-name`→`--aws.firewall-name`, `--gcp.firewall`→`--gcp.firewall-name`, `--aws.subnet-id`→`--aws.placement`.
  * Expiry flags unified to `--expire-in` (`cluster add expiry`, `client configure expiry`; matching `instances change-expiry`).
  * `net block|loss-delay`: `--source-node-list`→`--source-nodes`, `--destination-node-list`→`--destination-nodes`. `files sync`: `--source-name`→`--source`, `--dest-name`→`--destination`, `--destn-nodes`→`--destination-nodes`.
  * `volumes create`: `--volume-type`→`--type`; added `-n/-d/-o/-t` shorts. `inventory expire`: `--aws-expire-eksctl`→`--expire-eks`. `inventory delete-project-resources`: `--expiry`→`--with-expiry`. `client create graph`: `-C/--cluster-name`→`-C/--seed-cluster`.
  * `--dry-run` and `--no-wait` no longer have single-letter shorts anywhere (previously a mix of `-n`, `-d`, `-w`); `-n` always means `--name`.
  * Various short-flag alignments: owner filters are `-O/--owner` on all list commands; volumes filters use `-b/--backend`/`-z/--zone` (matching instances); `xdr connect -S`→`-s/--source`; `xdr create-clusters -N`→`-D/--destinations`; template create/destroy agree on `-v/--distro-version` and `-A/--aerospike-version`.
  * `client create` public-IP compatibility flags (`--public-ip`/`--external-ip`) removed; instance public-IP assignment follows the backend policy plus the standard `--aws.no-public-ip`/`--gcp.no-public-ip` flags.
* Security: SSH host keys are now remembered and verified. AeroLab learns each instance's host key the first time it connects, keyed by cluster UUID plus node number, and checks it on every later connection. Keys are forgotten automatically when instances are created or terminated, so reused node numbers relearn cleanly.
  * A changed key logs a loud warning and is relearned by default. Set `aerolab config backend --ssh-strict-host-key` to refuse the connection instead.
  * New `aerolab config host-keys list|forget` command to inspect the store and prune entries (`-n` cluster, `-l` nodes, `--all`).
  * The store lives at `$AEROLAB_HOME/projects/<project>/known-hosts.json` (mode 0600).
  * `agi create` now records the external SFTP server's host key fingerprint and the AGI ingest service verifies it, so the SFTP password cannot be captured by an intercepting host.
  * Fixed: the Web UI terminal dialed SSH directly and ignored the GCP IAP tunnel; it now goes through the shared SSH path.
* Security: AWS security groups and GCP firewall rules are now per user and locked to the caller's own address. AeroLab no longer creates any rule allowing SSH from `0.0.0.0/0`.
  * Instances get a group named after the user who created them (`AEROLAB_DEFAULT_{project}_{owner}_{vpc-id}` on AWS, `aerolab-o-{owner}-{vpc}` plus `aerolab-oi-{owner}-{vpc}` on GCP), so several people can share one account without opening each other's instances up. The per-user group allows every port from the caller's address (not only SSH), and allows instances that share the group to talk to each other on every port. Existing SSH-only groups are widened on the next command that touches an instance.
  * Access self-heals. Any command that touches an instance - `attach shell`, `files upload`, `aerospike start`, `instances start` and the rest - first re-locks your group to the address you are on now, and attaches your group to instances created by other people. Nothing is ever detached, so their access is untouched.
  * Your public address is discovered from `api.ipify.org`. Override it with `aerolab config backend --firewall-cidr 203.0.113.0/24` or the `AEROLAB_FIREWALL_CIDR` environment variable, which is needed behind a NAT gateway or VPN and when hosting the Web UI, where the discovered address is the server's rather than the browser user's.
  * Turn the automatic handling off with `aerolab config backend --no-firewall-autolock` or `AEROLAB_FIREWALL_AUTOLOCK=0`.
  * AGI keeps ports 80 and 443 open to the world, since Let's Encrypt validation and shared dashboard links need them; its SSH is caller-locked and its group is now per user too.
  * Fixed: `config aws lock-security-groups` and `config gcp lock-firewall-rules` never worked. They did not resolve `discover-caller-ip`, did not turn a bare address into a `/32`, and sent an update with no action, which the backend rejected. They now also default to your own per-user groups and to all ports, and revoke whatever else those ports allowed.
  * Security groups created by earlier versions keep working for the instances already using them; AeroLab warns when one of them still allows SSH from the whole internet.
  * `webui --unique-firewalls` is deprecated: per-user naming is now unconditional.
* Security: AGI auth tokens are generated with `crypto/rand` instead of a time-seeded `math/rand`, and token file names are random rather than timestamps. Existing tokens keep working; regenerate them with `aerolab agi add-auth-token` to get the stronger randomness.
* Security: The AGI proxy compares auth tokens in constant time against stored SHA-256 digests, so a token can no longer be recovered byte by byte from response timing.
* Security: AGI access URLs now carry the token in the URL fragment (`/agi/menu#AGI_TOKEN=...`) rather than the query string, keeping it out of server access logs, `Referer` headers and proxy history. Existing `?AGI_TOKEN=` links continue to work. The auth cookie is now `HttpOnly`, `SameSite=Lax` and `Secure` when the proxy serves HTTPS.
* Security: `aerolab webui` refuses to start with `--auth=none` on a non-loopback listen address, since the Web UI grants full command execution and root shell access. Use `--auth=basic`/`--auth=token`, bind to loopback, or pass `--insecure-allow-remote-noauth` to override. It also warns when credentials would cross a non-loopback network in cleartext, and when `--cors-origins` is `*` on a non-loopback bind.
* Security: Web UI file uploads now reject tar entries that escape the destination directory, along with symlink, hardlink, device and FIFO entries, and no longer carry setuid/setgid bits across from the archive.
* Security: Telemetry redacts secrets centrally. Fields tagged `telemetry:"redact"` are scrubbed from the recorded parameters, the matching flags are scrubbed out of the recorded command line, secret-shaped config defaults are dropped, and secret-shaped `AEROLAB_*` environment variables are masked.
* Security: The AeroLab config file is created as `0600` inside a `0700` directory, and existing group- or world-readable config files are tightened on startup.
* Security: AGI ingest now rejects tar, zip and rar entries that escape the extract directory (ZipSlip) or are links/devices, and refuses to pass collectinfo paths outside the collectinfo directory to `asadm`.
* Security: GCP OAuth access tokens are no longer written to debug logs; a short SHA-256 fingerprint is logged instead.
* Security: The release-mail GitHub Action no longer interpolates the dispatched version into `run:` scripts; it is passed via `env` so a crafted input cannot break out of the shell.
* `cluster attach` / `client attach` / `attach *` / `instances attach`: `--detach` now implies `--no-terminal` (no PTY), matching v7. A PTY hangup on session close was killing backgrounded commands such as `nohup asbench ... &`.
